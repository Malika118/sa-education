# Регистрация пользователя в мобильном приложении

## 1. Название задачи

Регистрация пользователя в мобильном приложении интернет-магазина.

## 2. Цель

### Какую проблему решаем

На данный момент пользователи могут пользоваться приложением только как гости. Это приводит к следующим проблемам:

- Пользователь теряет содержимое корзины при смене устройства.
- Невозможно посмотреть историю заказов.
- Нельзя сохранить адрес доставки для повторного использования.
- Отсутствует персональная бонусная программа и скидки.
- Маркетинг не имеет возможности делать персонализированные предложения.

### Какую пользу получит пользователь

- Сохранение корзины между устройствами и сессиями.
- Доступ к истории заказов в любой момент.
- Возможность сохранить адрес доставки и не вводить его заново при каждом заказе.
- Участие в бонусной программе и получение персональных скидок.
- Ускорение оформления заказов благодаря автозаполнению данных профиля.

### Зачем это компании

- Рост повторных продаж за счёт персонализированных предложений.
- Увеличение среднего чека благодаря бонусной программе.
- Сбор данных о пользователях для улучшения продукта и маркетинга.
- Снижение количества брошенных корзин за счёт их сохранения в аккаунте.


## 3. Описание функции

### Кто может пользоваться функцией

Любой новый пользователь мобильного приложения, у которого ещё нет аккаунта. Гостевые пользователи, желающие создать личный кабинет.

### Где находится экран регистрации

Экран регистрации доступен со следующих экранов:

- С главного экрана приложения (кнопка «Профиль», затем «Зарегистрироваться»).
- С экрана корзины при попытке оформить заказ без авторизации.
- С экрана избранного при попытке сохранить товар без авторизации.

### Поля, которые заполняет пользователь

| Поле | Тип | Обязательность | Примечание |
| :--- | :--- | :--- | :--- |
| Имя | Текстовое поле | Обязательное | Минимум 2 символа. Только буквы, пробелы и дефис. |
| Фамилия | Текстовое поле | Необязательное | Минимум 2 символа, если заполнено. Только буквы, пробелы и дефис. |
| Email | Текстовое поле (тип email) | Обязательное | Должен соответствовать формату email |
| Телефон | Текстовое поле (тип tel) | Необязательное | Формат: +7 XXX XXX-XX-XX. Маска ввода применяется автоматически. |
| Пароль | Поле с паролем (скрытый ввод) | Обязательное | Минимум 8 символов. Должен содержать хотя бы одну заглавную букву, одну строчную букву и одну цифру. |
| Подтверждение пароля | Поле с паролем (скрытый ввод) | Обязательное | Должно полностью совпадать с полем «Пароль». |

### Дополнительные элементы на экране

| Элемент | Описание |
| :--- | :--- |
| Чекбокс согласия с политикой конфиденциальности | Обязательный. Текст: «Я принимаю условия Политики конфиденциальности и даю согласие на обработку персональных данных». |
| Чекбокс согласия на получение рекламных рассылок | Необязательный. По умолчанию не отмечен. |
| Кнопка «Зарегистрироваться» | Основное действие. Неактивна, пока все обязательные поля не заполнены корректно и чекбокс согласия не отмечен. |
| Кнопка «Показать пароль» | Иконка глаза рядом с полями пароля. Позволяет временно отобразить введённый пароль. |
| Ссылка «Уже есть аккаунт? Войти» | Переводит пользователя на экран входа. |

### Что происходит после успешной регистрации

1. Система создаёт учётную запись пользователя.
2. На указанный email отправляется письмо с подтверждением регистрации.
3. Пользователь автоматически авторизуется в приложении.
4. Пользователь перенаправляется на главный экран приложения.
5. Гостевая корзина (если была) объединяется с корзиной нового аккаунта.


## 4. Основной сценарий

Предусловие: Пользователь не авторизован в приложении. У него нет ранее созданного аккаунта.

| Шаг | Действие | Реакция системы |
| :--- | :--- | :--- |
| 1 | Пользователь открывает экран регистрации. | Система отображает форму регистрации с пустыми полями. Кнопка «Зарегистрироваться» неактивна. |
| 2 | Пользователь вводит имя. | Если имя соответствует требованиям, поле считается валидным. |
| 3 | Пользователь вводит фамилию (опционально). | Поле необязательное, может остаться пустым. |
| 4 | Пользователь вводит email. | Система проверяет формат email в реальном времени. |
| 5 | Пользователь вводит номер телефона (опционально). | Система применяет маску ввода. |
| 6 | Пользователь вводит пароль. | Система скрывает вводимые символы. При соответствии требованиям поле считается валидным. |
| 7 | Пользователь вводит подтверждение пароля. | Система проверяет совпадение с полем «Пароль». |
| 8 | Пользователь отмечает чекбокс согласия с политикой конфиденциальности. | Система фиксирует согласие. |
| 9 | Система активирует кнопку «Зарегистрироваться». | Кнопка становится доступной для нажатия. |
| 10 | Пользователь нажимает кнопку «Зарегистрироваться». | Система блокирует кнопку, отображает индикатор загрузки. |
| 11 | Система проверяет, что email не занят. | Если email свободен, система создаёт новую учётную запись. |
| 12 | Система отправляет письмо с подтверждением. | Письмо отправляется в фоновом режиме. |
| 13 | Система автоматически авторизует пользователя. | Пользователь перенаправляется на главный экран. Корзина объединяется с корзиной аккаунта. |


## 5. Ошибки и альтернативные сценарии

### 5.1. Пользователь ввёл некорректный email

Триггер: Формат введённого email не соответствует стандарту.

Поведение системы:
- Поле email подсвечивается красным.
- Отображается текст ошибки: «Введите корректный адрес электронной почты».
- Кнопка «Зарегистрироваться» остаётся неактивной.

### 5.2. Пароль не соответствует требованиям к сложности

Триггер: Пароль короче 8 символов или не содержит заглавную букву, строчную букву и цифру.

Поведение системы:
- Поле пароля подсвечивается красным.
- Отображается текст ошибки: «Пароль должен содержать не менее 8 символов, включая заглавную букву, строчную букву и цифру».
- Кнопка «Зарегистрироваться» остаётся неактивной.

### 5.3. Пароль и подтверждение пароля не совпадают

Триггер: Значения в полях «Пароль» и «Подтверждение пароля» различаются.

Поведение системы:
- Поле подтверждения пароля подсвечивается красным.
- Отображается текст ошибки: «Пароли не совпадают».
- Кнопка «Зарегистрироваться» остаётся неактивной.

### 5.4. Email уже зарегистрирован

Триггер: Пользователь ввёл email, который уже существует в системе.

Поведение системы:
- Кнопка разблокируется после ответа от сервера.
- Отображается текст ошибки: «Пользователь с таким email уже зарегистрирован».
- Отображается ссылка: «Войти с этим email?».

### 5.5. Обязательные поля не заполнены

Триггер: Не заполнено одно или несколько обязательных полей или не отмечен чекбокс согласия.

Поведение системы:
- Кнопка «Зарегистрироваться» остаётся неактивной.
- Система не позволяет нажать кнопку.

### 5.6. Отсутствует интернет-соединение

Триггер: Пользователь нажал «Зарегистрироваться», но устройство не подключено к интернету.

Поведение системы:
- Кнопка разблокируется после таймаута (15 секунд).
- Отображается сообщение: «Отсутствует подключение к интернету. Проверьте соединение и попробуйте снова».
- Введённые данные сохраняются в полях формы.

### 5.7. Сервер недоступен

Триггер: Серверная часть не отвечает или возвращает ошибку.

Поведение системы:
- Кнопка разблокируется после получения ответа об ошибке или по таймауту.
- Отображается сообщение: «Сервис временно недоступен. Пожалуйста, попробуйте позже».
- Введённые данные сохраняются в полях формы.

### 5.8. Пользователь несколько раз нажал кнопку «Зарегистрироваться»

Триггер: Пользователь быстро нажимает кнопку два или более раз.

Поведение системы:
- После первого нажатия кнопка блокируется и отображается индикатор загрузки.
- Повторные нажатия игнорируются до получения ответа от сервера.
- Отправляется только один запрос на регистрацию.


## 6. Ограничения

### Технические ограничения

| Ограничение | Значение |
| :--- | :--- |
| Способ регистрации | Только по email. Регистрация через социальные сети в данной версии не поддерживается. |
| Минимальная длина пароля | 8 символов. |
| Платформа | Только мобильное приложение. |
| Версия ОС | Android 10.0 и выше, iOS 15.0 и выше. |
| Язык интерфейса | Русский. |
| Подтверждение email | Письмо отправляется, но аккаунт создаётся и пользователь авторизуется сразу. |
| Капча | В текущей версии не внедряется. |
| Вставка пароля из буфера | Разрешена. |

### Бизнес-ограничения

| Ограничение | Значение |
| :--- | :--- |
| Возраст пользователя | Регистрация доступна только пользователям старше 18 лет. |
| Количество попыток регистрации | Не более 5 попыток с одного IP-адреса в течение 10 минут. |


## 7. Критерии приёмки

### Регистрация с валидными данными

1. Пользователь может зарегистрироваться, заполнив все обязательные поля корректными данными и отметив чекбокс согласия с политикой конфиденциальности.
2. После успешной регистрации пользователь автоматически авторизуется и перенаправляется на главный экран приложения.
3. На указанный email отправляется письмо с подтверждением регистрации.
4. Гостевая корзина (если она была) объединяется с корзиной нового аккаунта.

### Валидация полей

5. Система не позволяет зарегистрироваться, если поле Email заполнено в некорректном формате. Отображается сообщение об ошибке.
6. Система не позволяет зарегистрироваться, если пароль не соответствует требованиям к сложности. Отображается сообщение об ошибке.
7. Система не позволяет зарегистрироваться, если значения в полях «Пароль» и «Подтверждение пароля» не совпадают. Отображается сообщение об ошибке.
8. Кнопка «Зарегистрироваться» остаётся неактивной, пока все обязательные поля не заполнены корректно и чекбокс согласия не отмечен.

### Обработка дубликатов

9. Система не позволяет зарегистрировать уже существующий email. Отображается сообщение: «Пользователь с таким email уже зарегистрирован».
10. При попытке регистрации с занятым email отображается ссылка «Войти с этим email?».

### Обработка ошибок соединения

11. При отсутствии интернет-соединения отображается сообщение: «Отсутствует подключение к интернету. Проверьте соединение и попробуйте снова». Введённые данные сохраняются.
12. При недоступности сервера отображается сообщение: «Сервис временно недоступен. Пожалуйста, попробуйте позже». Введённые данные сохраняются.

### Защита от двойной отправки

13. При нажатии на кнопку «Зарегистрироваться» она блокируется на время обработки запроса. Повторные нажатия игнорируются. Отправляется ровно один запрос на регистрацию.

### Безопасность

14. Пароль передаётся на сервер в защищённом виде (по протоколу HTTPS с шифрованием).
15. Пароль хранится на сервере в хешированном виде. Открытый пароль не сохраняется.
16. Пользователь может временно отобразить вводимый пароль, нажав на иконку глаза рядом с полем пароля.

### UI/UX

17. Поле «Телефон» имеет маску ввода в формате +7 (XXX) XXX-XX-XX.
18. Все сообщения об ошибках отображаются на русском языке, рядом с соответствующим полем, красным цветом.
19. Ссылка «Политика конфиденциальности» в чекбоксе согласия кликабельна и ведёт на актуальный документ.

### Лимиты

20. При превышении лимита попыток регистрации (5 попыток с одного IP за 10 минут) отображается сообщение: «Слишком много попыток. Пожалуйста, попробуйте позже».
